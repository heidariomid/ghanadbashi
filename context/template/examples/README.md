# Examples

The real documents from the first project (the bakery), kept as worked examples
of the brief format. **Not instructions** — the design direction in `prompt` was
superseded when the client approved a photography-led design.

| File | What it is | What to learn from it |
| --- | --- | --- |
| `prompt` | The full phase-0 brief, ~400 lines | How specific a brief needs to be to get a non-generic result: exact stroke widths, named palette constraints, a "remove rather than add" rule, and an explicit instruction to report honestly when visuals could not be checked |
| `chat` | The short covering message sent with it | Asking for a plan on type scale, palette and structure *before* code, and requiring one illustration to be approved before the rest were drawn — a cheap way to catch a wrong direction early |

The lesson the `prompt` file itself demonstrates: it produced exactly what it
asked for — a careful, illustration-led design — and the client then chose
something else entirely. A detailed brief does not remove the need for phase 0;
it only makes the demo worth showing.
